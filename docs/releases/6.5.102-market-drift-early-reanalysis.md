# Cloud 6.5.102 — Market-Drift Early Reanalysis

Status: DEMO / PAPER ONLY

MT5 stable package remains 6.3.38:
- DataBridge 1.55
- DataBridge core 1.32
- Sequence EA 3.45
- Renderer V662

## Purpose

Scheduled session analysis remains the normal backbone, but the Cloud no longer
has to wait for the next fixed analysis time when price has materially travelled
away from the currently selected, unowned HTF map.

## Event-driven trigger

On every fresh complete MT5 snapshot the scheduler can request a new analysis
when all of the following are true:

- paper/demo mode;
- there is a selected PRIMARY map;
- no acquired thesis owner exists;
- the selected zone is still only ARMED/WATCH (no live contact / M1 handoff);
- price is still on the valid approach side of the zone, not through it;
- the existing analysis is at least 10 minutes old;
- the selected zone has become at least 2.0 H1 ATR away from live price.

The refresh reason is recorded as
`MARKET_DRIFT_REANALYSIS:<zone>:<distance>H1ATR`.

A 0.5 H1 ATR distance-step latch prevents repeated analysis on every snapshot.
The trigger can fire again only after materially further travel, a different
selected zone, or after the condition clears and later reappears.

## Safety boundary

This trigger refreshes the HTF map only. It does not invalidate the old zone,
force a new zone, acquire thesis ownership, enable M1 authority, change risk,
or send an order. If the fresh analysis finds no better qualified battlefield,
the same existing zone can remain the valid map.

Active thesis ownership always suppresses this drift refresh so an acquired
trade lifecycle cannot be replaced merely because price has moved away.

The existing scheduled, news, zone-contact, accepted-invalidation, thesis-state,
liquidity-reversal and M1-handoff refresh triggers remain unchanged.
