# Cloud 6.5.110 — live core handoff deadlock correction

Status: DEMO / PAPER ONLY

Runtime versions:
- Cloud 6.5.110
- Stable package 6.3.40
- DataBridge 1.57
- Sequence EA 3.47

## Incident reproduced

A source-exact A+ SELL map could be correctly published and later contacted by
live price while the execution plan remained WATCH_ONLY.

The 30 September 2026 example exposed the failure clearly:

- selected zone: `PZ_H4H1_SELL_1790755200`
- tactical core: 4193.60-4202.19
- exact geometry published: 14:12:37
- post-publication live contact persisted: 14:12:52
- validation ledger lifecycle: INTERACTING
- MT5 / dashboard plan: MAP VALID / RETEST PENDING
- Cloud authority: NONE
- Sequence: CLOUD PLAN WATCH ONLY

This was not a zoning failure and it was not a Sequence polling failure.

## Root cause

Two Cloud state machines were using different clocks.

1. Snapshot ingestion correctly persisted exact post-publication core contact.
2. M1 authority promotion only ran inside `run_analysis()`.
3. The scheduler used the same zone id for both broad ATR approach and exact
   core contact. Once the approach was latched, entering the core did not create
   a new scheduler edge, so no fresh analysis was requested.
4. The previously saved Analysis object therefore remained `ARMED`, even while
   the publication ledger already knew that the core had been contacted.
5. `run_analysis()` also cleared `Analysis.approved` merely because an
   execution handoff was not active yet, coupling structural-map approval to
   execution timing.

Strategic Sequence 3.47 models sit downstream of Cloud execution authority, so
adding more M1 models could not solve this upstream deadlock.

## Correction

### Edge-sensitive scheduler refresh

Scheduler interaction truth now distinguishes:

- `APPROACH:<zone>`
- `CORE:<zone>`
- `CONTACT:<zone>:<live_touch_ts>`

An approach can no longer consume the later exact-core transition.

The persisted CONTACT token is also read from canonical publication truth. If a
brief live quote touch is recorded but price leaves the core before the scheduler
polls, the contact still triggers one fresh analysis and can recover the valid
reaction window.

### Structural approval is not execution permission

A structurally valid selected institutional map remains approved while ARMED.
Absence of a current handoff no longer mutates structural approval to false.

This does **not** make the map executable. The finalized MT5 plan remains
WATCH_ONLY until one of the existing execution authorities is actually earned:

- HTF_CORE_HANDOFF
- HTF_ZONE_SWEEP_HANDOFF
- LIQUIDITY_REVERSAL_HANDOFF

AI execution validation / PAPER fallback, target direction, RR, spread/news,
contract parity, risk sizing, closed-M1 confirmation and no-chase gates remain
unchanged.

## Why MT5 is unchanged

Sequence 3.47 already polls `/mt5/plan` continuously and correctly refuses an
order while `ea_mode != DUAL_BRANCH` or Cloud execution authority is NONE.
The defect was upstream: Cloud was not refreshing the plan at the exact contact
edge.

Therefore no MT5 reinstall or reattach is required for this release.

## Replay truth

The scheduler event timing changes replay execution authority timing. Replay
provenance is therefore advanced to Cloud 6.5.110 rather than claiming
compatibility with the older execution-event contract.

## Expected live behavior

For an unowned active A+/A/B+ map:

1. approach may request normal map refresh;
2. exact post-publication core contact creates a distinct refresh edge;
3. the fresh analysis can mark the zone M1_READY and establish the appropriate
   macro handoff;
4. Sequence then searches the existing sniper / rescue / escape / strategic M1
   models;
5. an order still requires the normal closed-M1 professional confirmation and all
   risk/safety gates.

No price, zone or trade direction is hard-coded by this correction.
