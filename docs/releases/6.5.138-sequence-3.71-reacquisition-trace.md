## Failure addressed

A still-valid acquired thesis can complete P0, later revisit the same frozen institutional zone, and remain stuck at `M1_SWEEP` even though the relevant M1 event occurred earlier in the reacquisition cycle.

Sequence 3.70 already supported campaign persistence, pre-handoff reconstruction, original-zone R1/R2 reacquisition and causal displacement continuation. The repair in 3.71 closes two implementation/observability gaps:

1. P0 and R1/R2 used the same 30-bar Model-1 sweep search window. A legitimate R1/R2 zone-contact/sweep could age out before the later bounded value/retest confirmation completed.
2. local Sequence state recorded campaign/contact reconstruction truth, but the heartbeat omitted some of those fields, while the dashboard also labelled all Model-1 waits as a primary sequence.

## R1/R2 original-zone reacquisition repair

P0 is unchanged and still uses the inherited `SweepWindowBars` contract, 30 bars by default.

Only R1/R2 original-zone reacquisition can search farther back for the causal zone-contact and micro-liquidity sweep. The default bounded reconstruction window is 90 closed M1 bars.

This is not permission to enter from an old sweep. The reconstructed chain still requires the same model:

- valid active thesis and macro authority;
- original institutional-zone contact;
- valid M1 micro-liquidity sweep;
- CLOSED M1 micro structure shift;
- causal M1 OB/FVG;
- bounded PD-array retest;
- latest CLOSED directional M1 confirmation;
- protected M1 swing execution stop;
- minimum RR to an open objective;
- spread/snapshot/parity/broker safety;
- an available R1/R2 campaign slot.

The sweep-to-MSS relationship is separately bounded to 45 M1 bars by default. An ancient sweep therefore cannot be paired with an unrelated current structure break.

## Continuation re-entry remains separate

The existing causal displacement OB/FVG continuation family remains a separate R1/R2 path. This release does not merge original-zone reacquisition with displacement-structure continuation.

That distinction remains:

- **Original-zone reacquisition:** price returns to the frozen HTF owner zone and a new Model-1/2 cycle is evaluated.
- **Displacement continuation:** price pulls back into the causal M1 OB/FVG created by the successful same-thesis displacement.

Both consume the existing campaign re-entry allowance. Neither creates R3 or resets the thesis.

## Forensic telemetry

Sequence 3.71 publishes an explicit `opportunity_slot` (`P0`, `R1`, `R2`, or cap reached).

When Model 1 remains at the sweep stage, telemetry now records:

- number of M1 bars scanned;
- best candidate sweep timestamp;
- candidate liquidity level;
- candidate sweep price;
- clearance through the liquidity level in points;
- explicit rejection reason:
  - `NO_ZONE_CONTACT_IN_SWEEP_WINDOW`
  - `NO_MICRO_LIQUIDITY_LEVEL`
  - `SWEEP_BUFFER_NOT_CLEARED`

The heartbeat now also carries the campaign key, zone-contact timestamp and whether the reconstructed event preceded the Cloud handoff. These fields were already present in local Sequence state but were previously absent from the heartbeat.

The dashboard uses the opportunity slot to distinguish `M1 PRIMARY SEQUENCE FORMING` from `R1/R2 ZONE RE-ACQUISITION FORMING`.

## Risk and management invariants

This release does **not** change:

- P0 sweep window;
- thesis grade/risk percentages;
- P0/R1/R2 allocation or maximum re-entry count;
- objective lifecycle rules;
- protected-swing stop logic;
- minimum-RR order gate;
- spread, parity or broker guards;
- accepted-zone flip logic;
- position management, break-even, objective locks, partials or runner trailing.

The 3.71 regression suite explicitly compares the `ManagePositions()` function with 3.70 to prevent an entry-state repair from changing trade management.
