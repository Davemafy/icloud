# Cloud 6.5.106 — Fresh M1 location truth

Status: DEMO / PAPER ONLY

MT5 stable package is unchanged:
- Stable 6.3.38
- DataBridge 1.55
- Sequence EA 3.45

## Live verification finding

Cloud 6.5.105 correctly separated the selected map state from sticky thesis
ownership, but the dashboard still reused the legacy m1_handoff_ready boolean for
two different meanings.

For an acquired thesis, that boolean can remain true because macro execution
authority is intentionally preserved. At the same time Sequence can correctly be
at:

LOCATION / WAITING_FOR_VALID_LOCATION

which means there is no fresh M1 entry location yet.

The result was a confusing display:
- selected map: THESIS OWNER ACTIVE / FRESH M1 REQUIRED
- Sequence: LOCATION / WAITING_FOR_VALID_LOCATION
- dashboard context/checklist: Current M1 location handoff YES

The engine behavior was safe; the read-only wording was not precise enough.

## 6.5.106 behavior

The journal now exposes two separate truths:

1. Macro thesis / handoff authority
   - sticky for an acquired thesis until lifecycle release
   - permits Sequence to keep searching the owner direction
   - is not a fresh entry signal

2. Fresh M1 entry location
   - derived from live Sequence gate telemetry
   - false while Sequence is at LOCATION / WAITING_FOR_VALID_LOCATION
   - becomes true only after Sequence has a current entry-location context and
     advances beyond LOCATION

The before-entry checklist now displays both values separately. A valid owner
with no current M1 location therefore reads approximately:

- Macro thesis / handoff authority active: YES
- Fresh M1 entry location active: NO

and Execution readiness reads:

THESIS OWNER / WAITING FOR FRESH M1 LOCATION

until Sequence advances.

The institutional brief also stops describing owner continuation as PAPER
M1_READY. It now calls it THESIS_OWNER_CONTINUATION and explicitly states that
the preserved macro authority is not a fresh entry location.
