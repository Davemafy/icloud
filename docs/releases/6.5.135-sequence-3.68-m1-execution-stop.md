# Cloud 6.5.135 / MT5 Stable 6.4.8 — causal M1 execution stop

## Scope

- Cloud: 6.5.135
- MT5 stable package: 6.4.8
- DataBridge: unchanged at 1.58
- Sequence EA: 3.68
- DEMO / PAPER ONLY

## Root cause

The current MIN_RR block was not caused by a missing M1 confirmation. It was caused by applying the full HTF envelope distal as the order-level stop after the M1 model had already confirmed.

That mixed two different invalidations:

- HTF zone invalidation: when the institutional thesis itself is no longer valid.
- M1 execution invalidation: when the confirmed trade entry pattern has failed.

On a wide H4/H1 envelope, using the HTF distal as the order SL can make a precise M1 entry mathematically incapable of meeting minimum RR even after a valid reaction.

## Sequence 3.68 contract

After a valid CLOSED M1 execution model confirms, the order stop is placed beyond the causal M1 structural anchor with the existing maximum spread / ATR / broker-stop buffer.

The HTF distal boundary remains unchanged and continues to control thesis invalidation, accepted invalidation, flip logic and owner release.

Therefore:

- a stopped M1 execution does not automatically invalidate the HTF thesis;
- R1/R2 can still operate inside the same campaign/risk budget while the thesis remains valid;
- the 0.30% maximum thesis/campaign risk architecture is unchanged;
- minimum RR remains fail-closed at order time;
- RR is now measured against the actual M1 execution structure instead of remote HTF-envelope width.

## Transparency

Sequence now publishes the last evaluated:

- candidate entry
- candidate SL
- candidate target
- actual RR
- required RR
- stop basis

When minimum RR blocks a trade, the gate reason includes these values. The dashboard also surfaces a Candidate audit so a blocked order is no longer opaque.

## Accepted-zone flips

The first accepted-zone flip entry now follows the same execution-stop separation after its mandatory retest and M1 confirmation. The failed HTF zone remains lifecycle/invalidation context rather than a remote order stop.

## Safety retained

The following are not removed:

- accepted M15 invalidation
- spread/snapshot safety
- owner/authority parity
- duplicate-order protection
- position-protection requirements
- campaign risk cap and risk sizing
- valid target beyond entry
- minimum RR
- no-chase / model-specific M1 confirmation
- broker minimum stop/volume constraints

This release removes an execution-architecture mismatch, not the professional safety layer.
