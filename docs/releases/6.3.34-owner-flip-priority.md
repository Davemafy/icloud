# Trade Zone 6.3.34 — Owner / Accepted-Flip Runtime Priority

Status: DEMO / PAPER ONLY

- DataBridge: 1.52
- Sequence EA: 3.44
- Cloud companion: 6.5.95+

## Why this release exists

A persisted accepted-zone-flip candidate could remain in `accepted_flip_state.txt` while a
newer non-terminal thesis owner was legitimately active. Sequence refreshed the current
Cloud plan first, but then the accepted-flip evaluator set `g_tzExecutionAuthority=NONE`
before its safety checks. During a live spread block this left the heartbeat reporting
`Sequence authority NONE` even though Cloud correctly retained
`HTF_CORE_HANDOFF` for the active owner.

## 3.44 behavior

Sequence now applies this runtime hierarchy:

1. refresh current Cloud plan, owner mirror, risk, parity and safety truth;
2. if a persisted flip exists, verify whether the current selected plan is still owned by
   a non-terminal acquired owner;
3. when owner identity, direction and authority all match, keep the accepted flip dormant
   and continue through the normal owner execution path;
4. the accepted flip remains persisted for audit/expiry and becomes eligible again only
   after the owner no longer has priority;
5. spread, stale-data, news, parity, risk, target, M1 confirmation and no-chase guards are
   unchanged.

A safety hold therefore suspends order permission without erasing the owner's macro
authority. No new trade is authorized by this change.
