# Cloud 6.5.127 / Stable 6.4.3 — model-specific sniper confirmation correction

## Scope

This release corrects the execution contract introduced in Sequence 3.62. The Master Sniper contract has three independent sniper entry families. Only Model 1 requires a separate closed M1 micro-structure shift.

### Model 1 — Sniper PD retest

Zone contact/reconstruction -> micro-liquidity sweep -> CLOSED M1 micro-structure shift -> causal OB/FVG -> bounded retest -> closed directional M1 confirmation.

The M1 micro-structure shift remains mandatory.

### Model 2 — Recent-zone engulfing

Valid/recent institutional-zone context -> CLOSED directional real-body engulfing -> entry safety/risk gates.

No separate M1 micro-structure shift is required. The engulfing candle is the model's confirmation event.

### Model 3 — Institutional breakout

Qualified London/New York opening-range or M1 balance boundary -> CLOSED displacement break -> acceptance -> retest -> CLOSED directional M1 confirmation -> entry safety/risk gates.

No separate post-retest M1 micro-structure shift is required. Direct breakout-candle chasing remains disabled.

## Regression protection

CI now asserts that:

- Model 1 still contains the M1 micro-structure-shift requirement.
- Model 2 contains no separate post-engulfing MSS blocker.
- Model 3 contains displacement, acceptance, retest, directional close and no-chase gates but no post-retest MSS blocker.
- Both primary and accepted-flip evaluation use the model-specific confirmation dispatcher.
- The dashboard and execution-policy telemetry report the same three-model contract.

## Live-state interpretation

Removing the incorrect Model 2/3 MSS gate does not convert an incomplete setup into a market order. A Model 2 trade still needs a valid closed engulfing at the authorized location. A Model 3 trade still needs a qualified boundary, displacement break, acceptance, retest and closed directional confirmation. If those events have not occurred, the correct state remains wait/no execution.
