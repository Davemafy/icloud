# MT5 stable 6.4.17 — Sequence 3.76 model-complete authorization

DEMO / PAPER ONLY.

## Scope

Sequence 3.76 is a narrow execution-state correction on top of the 3.75 canonical-liquidity foundation.

The canonical attached BSL/SSL sweep/reclaim remains mandatory for the primary campaign. The change removes redundant downstream authorization after a model has already completed its own M1 confirmation chain.

## Model contract

- Model 1: canonical campaign liquidity -> M1 sweep -> micro MSS -> causal fresh OB/FVG -> pullback -> CLOSED directional M1 -> execution qualification.
- Model 2: canonical campaign liquidity -> valid recent institutional-zone context -> CLOSED directional real-body engulfing -> execution qualification. No Model-1 MSS/pullback inheritance.
- Model 3: canonical campaign liquidity -> boundary displacement break -> acceptance -> retest -> CLOSED directional confirmation -> execution qualification. No Model-1 MSS/pullback inheritance.

No fourth rejection model is introduced.

## P0 / R1 / R2 campaign continuity

P0/B0 establishes and stores the exact canonical liquidity proof only after an order actually opens.

R1/R2 inherit that proof only inside the same owner acquisition, zone, side and canonical level. They do not require a second canonical external-liquidity sweep.

R1/R2 still require a legitimate new model-specific opportunity. The completed model chain supplies that freshness; an old P0 confirmation is not permission to chase.

Late-stage protection remains: after TP1 and TP2 are consumed, a new R1/R2 still requires owner-zone reacquisition before another continuation entry can proceed.

## Downstream invariants retained

- protected confirmed M1 swing execution stop;
- HTF thesis invalidation remains separate from order stop;
- remaining-objective direction check;
- actual-entry minimum RR;
- parity revalidation;
- spread and research safety guards;
- thesis risk budget and re-entry cap;
- accepted-zone flip and independent liquidity-reversal families remain separate.

For canonical Models 1/2/3, the CFD tick-volume order-flow proxy remains telemetry/confluence and cannot become an undocumented post-confirmation authorization veto.
