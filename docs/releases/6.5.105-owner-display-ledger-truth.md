# Cloud 6.5.105 — Thesis-owner display truth and canonical validation samples

Status: DEMO / PAPER ONLY

MT5 stable package remains unchanged:
- Stable 6.3.38
- DataBridge 1.55
- DataBridge core 1.32
- Sequence EA 3.45

## Why this release exists

The 6.5.104 live test showed correct execution behavior but two read-only truth
problems remained:

1. A sticky acquired thesis could still be labelled "M1 HANDOFF ACTIVE" long
   after price had travelled away from the original handoff location. Thesis
   ownership and a current M1 entry handoff are different states.
2. The validation ledger counted repeated exact-envelope publications from
   reanalysis of the same institutional source/core as independent research
   samples. Because the shared lifecycle row already contained a later confirmed
   reaction, this could produce an impossible reaction-after-contact percentage
   above 100%.

## 6.5.105 behavior

### Owner versus fresh M1 timing

When the selected zone is the active acquired thesis owner, trader-facing Cloud
and MT5 render feeds now display:

THESIS OWNER ACTIVE / FRESH M1 REQUIRED

instead of treating the stored M1_READY readiness as a current entry handoff.

The direction lock, target lifecycle and ownership anchor are unchanged.
Sequence still controls actual entry timing and still requires a fresh
same-direction M1 confirmation/value sequence before any new order.

### Canonical validation accounting

The raw zone_publications table remains untouched as a forensic exact-geometry
audit trail.

The read-only Master Sniper validation ledger now groups repeated publications
by:

direction + source timeframe + source timestamp + tactical core

so repeated reanalysis of the same institutional source/core is one validation
sample. Envelope observations remain auditable and the ledger reports how many
raw exact-geometry observations were collapsed into that canonical sample.

The "reaction after live core contact" percentage now uses only reactions whose
confirmed-reaction timestamp is at or after that sample's actual live core
contact. Qualified reactions acquired through other paths, such as an outer-zone
sweep handoff, remain visible but are excluded from that percentage. Therefore
the percentage cannot be inflated by non-contact reactions or repeated
publication rows.

## Safety boundary

This release changes presentation and research accounting only.

It does not alter:
- HTF zone creation or ranking
- thesis acquisition or release
- target lifecycle
- risk sizing
- M15 invalidation
- M1 execution confirmation
- spread/news guards
- Sequence order logic

Backtest zoning provenance therefore remains 6.5.104; Cloud 6.5.105 is accepted
as a presentation/research-compatible runtime.

No MT5 reinstall or reattach is required.
