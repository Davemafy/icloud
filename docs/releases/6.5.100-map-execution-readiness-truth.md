# Cloud 6.5.100 — Map / Execution Readiness Truth

Status: DEMO / PAPER ONLY

Stable MT5 package: 6.3.37
- DataBridge 1.54
- DataBridge core 1.32
- Sequence EA 3.45

## Problem corrected

A structurally valid selected HTF zone could be displayed as `ARMED` and the
MT5 renderer could treat simple plan selection as visual execution authority.
That made a remote SELL map look like SELL execution readiness even when price
had not contacted the zone, no M1 handoff existed, and the finalized Cloud plan
was WATCH_ONLY.

Accepted-invalidated BUY/SELL geometry was already preserved by Cloud 6.5.99
as zero-authority opposite-side `FLIP_CONTEXT`. This release makes the active
map and execution lifecycle equally explicit.

## 6.5.100 behavior

- `ARMED` remains an internal compatibility state, but human presentation is
  `MAP VALID • RETEST PENDING`.
- `INTERACTING` is presented as zone contact with M1 confirmation pending.
- `M1_READY` is presented as an M1 handoff, not as a completed order signal.
- The dashboard has a dedicated **Selected map state** card, separate from
  **Execution readiness** and the live **Sequence execution gate**.
- A selected ARMED zone has zero visual execution authority in the MT5 zone
  feed. Selection alone can no longer make the renderer label it executable.
- A selected zone receives visual handoff authority only when its current
  readiness is `M1_READY`; Sequence still owns the final micro-gates and order
  permission.
- Acquired thesis ownership remains a separate lifecycle state and is labelled
  **THESIS OWNER**, not immediate execution readiness.
- Accepted-invalidated geometry remains context only, with zero original-side
  authority and mandatory retest + M1 confirmation for any flip.

No zone geometry, grade, risk, spread, runway, target, invalidation, M1 sequence,
or order-management rule is relaxed.
