# Cloud 6.5.111 / MT5 Stable 6.3.41 — entry-specific runway

Status: DEMO / PAPER ONLY

## Why this release exists

The finalized Cloud plan previously measured minimum usable runway from the
least-favourable edge of the entire tactical core. That is deliberately
conservative, but it can suppress a valid Master Sniper battlefield when one
part of the same core has sufficient objective space and the later M1 model
would enter from that better-priced sub-window.

This release does **not** reduce the minimum runway requirement and does not
move, widen, manufacture or regrade any HTF zone.

## New runway contract

Cloud now derives an execution-eligible sub-window inside the already-qualified
tactical core:

- BUY: maximum runway-safe entry = valid target minus required runway.
- SELL: minimum runway-safe entry = valid target plus required runway.
- If no price inside the tactical core can satisfy the existing minimum, the
  plan remains WATCH_ONLY with INSUFFICIENT_USABLE_RUNWAY.
- If a runway-safe sub-window exists, the plan may progress to M1 execution
  authority once all existing handoff gates pass.
- Sequence 3.48 recalculates runway from the **actual intended market entry
  quote** immediately before order send. If the quote no longer has enough
  runway, the order fails closed with ENTRY_SPECIFIC_RUNWAY_NOT_MET.

The existing trend/countertrend runway thresholds, target validity, minimum RR,
closed-M1 confirmation, no-chase rules, Master Sniper location authority,
first-entry distal-zone stop, risk sizing, spread/snapshot/news safety and
contract parity all remain in force.

## Rolling upgrade safety

Cloud 6.5.111 only enables the relaxed pre-M1 sub-window semantics after it sees
a fresh Sequence heartbeat at version 3.48 or newer. While Sequence 3.47 (or an
older runtime) is still running, Cloud keeps the previous conservative
least-favourable-core-edge runway guard.

Historical replay also remains on the prior conservative runway contract until
the dedicated MT5 replay harness receives the same actual-entry gate. This
prevents live/replay capability claims from drifting.
